# 普通学习者首次成功体验提案

**状态：** Target state；核心实现进行中，逐项事实见 [implementation-status.md](./implementation-status.md)
**上游变更：** `desktop-first-distribution`、`external-alpha-first-session`、`accessibility-preferences`
**目标用户：** 不会软件开发、只希望练习英语听力的普通学习者

## Why

DeepListener 已经具备差异化的句级精听、跟读、收藏和间隔复习能力，但用户在获得学习价值前仍可能遇到安装、数据库、FFmpeg、API 密钥、素材导入和术语理解等障碍。对普通学习者而言，这些都不是“学习英语”任务的一部分。

第一次使用的核心问题不是功能数量，而是用户能否在不理解软件工程概念的情况下完成一次有意义的英语句子练习，并确信失败不会丢失自己的媒体、密钥或学习记录。

本变更把“首次成功”定义为一条可观测、可恢复的用户旅程，而不是“应用成功启动”或“页面能打开”。

## 第一性原理

1. **用户购买的是听力进步，不是本地运行时。** Node.js、Prisma、SQLite、FFmpeg、环境变量和迁移命令不得成为 Desktop 用户任务。
2. **价值必须先于配置。** 用户应先通过真实英语语音理解产品价值，再决定是否配置转写服务商或导入个人媒体。
3. **每一步都必须保持行动能力。** 错误状态必须说明发生了什么、影响什么、下一步是什么；“重试”只能在重试可能成功时出现。
4. **失败不得放大用户损失。** 已上传媒体和已完成处理应尽量保留；转写失败不得默认要求重新选择、重新上传和重新付费。
5. **复杂度按需揭示。** FSRS、数据库、Provider、转写模型和内部训练状态只在帮助决策时出现；默认文案使用学习者语言。
6. **本地优先必须可验证。** Demo、字幕路径和就绪检查不得静默联系外部服务；密钥和私有媒体不得出现在诊断、日志或遥测中。
7. **发布证据必须来自目标用户。** 构建成功、截图漂亮和自动化测试通过都不能替代陌生用户的首次会话证据。

## 当前事实

- Desktop 路径已经具备自动数据库初始化、应用内服务商密钥配置、Demo 隔离和本地数据根等部分能力。
- 当前公开分发仍是 macOS Apple Silicon Alpha；Windows 普通用户没有正式 Desktop 路径。
- 当前 Demo 音频是 5 秒正弦波，不包含英语语音，无法证明句级精听价值。
- 当前新手引导会介绍 Library、Setup、Practice、Review，但完成按钮只关闭引导；桌面聚光区域还可能被遮罩拦截。
- Server/源码模式数据库未初始化时，资料库可能落入通用错误页，只提供无效的“重试”。
- 当前单文件导入在转写或建库失败时删除已写入媒体，没有跨失败重试句柄。
- 应用已经支持视频内嵌字幕，但尚未把“无需 API 密钥”的字幕路径组织成清晰的首次使用选项。
- 现有 `desktop-first-distribution/tasks.md` 的部分勾选状态落后于当前代码，实施前必须先对账，不能按旧状态重复开发。

## 用户价值假设

如果 DeepListener 提供受支持平台的可安装 Desktop 包、用真实英语 Demo 先展示学习闭环、自动处理本地运行时、把配置与错误变成可操作向导，并在转写失败后保留可恢复的导入任务，那么普通学习者可以在 5 分钟内完成第一句有效练习，并愿意继续导入自己的材料。

## 最小可行验证

在不修改真实用户数据的干净 Desktop 配置中，邀请 5 名不具备开发经验的英语学习者完成：

1. 安装并首次启动；
2. 不配置密钥，完成一条真实英语 Demo 句子的盲听、揭示和收藏；
3. 找到该句的后续复习入口；
4. 理解如何导入自己的媒体；
5. 遇到一个人为注入的可恢复错误并自行恢复。

若任一用户需要终端、开发术语解释或人工代操作，首次成功假设尚未成立。

## What Changes

- 增加启动就绪门控：数据库或关键运行时不可用时，不进入必然失败的业务页面。
- 把新手引导改为可执行任务，最后一个主按钮真正启动 Demo 或个人素材路径。
- 用有明确再分发权的真实英语语音替换正弦波 Demo，并覆盖完整学习闭环。
- 把 Provider 配置改成决策向导，说明推荐场景、费用风险、隐私边界和无需密钥的替代路径。
- 增加显式字幕导入/配对路径，使部分个人媒体无需外部转写服务。
- 将导入处理改为可恢复操作：保存阶段、错误类别、重试入口和清理策略。
- 对首次会话中的 FSRS、Vault、内部状态和技术词汇实行渐进披露。
- 建立键盘、屏幕阅读器、中文/英文、窄屏和缩放验收契约。
- 用干净机器与目标用户会话作为 Desktop 推广闸门。

## 与现有 OpenSpec 的关系

- 不替代 `desktop-first-distribution` 的数据根、迁移、备份、Electron、安全、签名或平台适配设计。
- 复用 `DLR-001` 自动初始化、`DFS-001` 双路径、`DFS-002/003` Demo、`DCS-001` UI 密钥配置等要求，并增加更严格的用户可操作性验收。
- `external-alpha-first-session` 已完成的可见 Demo 入口、盲听跳转和 Provider 诚实状态视为现有基线，不重新实现。
- `accessibility-preferences` 已完成的语言、主题和引导入口视为现有基线；本变更修正其实际交互与无障碍缺口。
- 实施前必须完成 OpenSpec 状态对账，将“代码已存在但任务未勾选”的条目标为已实现、部分实现或待验证。

## 数据安全影响

- 规划包含数据库启动门控和导入恢复，但不得直接操作 `prisma/dev.db`、`public/uploads/`、`public/videos/` 或 `.env*`。
- 任何导入暂存文件都属于用户媒体，必须位于受控数据根、具备路径逃逸防护、明确生命周期且不能静默删除。
- 若后续引入新的持久化导入任务或 Prisma schema，必须单独建立 Adversarial 合同、备份证据、迁移与回滚测试；不得为了方便重试而复用学习状态字段。
- Demo 记录必须继续使用独立所有权标记，删除 Demo 不得影响个人记录。

## Rollback

- UI 引导、文案和门控可按功能开关或单独提交回退，不修改学习数据。
- 新 Demo 资产替换必须保留可验证的来源、校验和及回退资产；回退不得删除用户创建的 Demo 学习记录，除非经过兼容处理。
- 可恢复导入采用暂存后原子提升；失败或回退时现有正式媒体和 Track 保持不变。
- Desktop 底座仍以现有 Server edition 作为维护者回退路径，但普通用户发布不得依赖该路径。

## Non-goals

- 不在本变更中实现云同步、账号、多用户、移动端、Linux 正式包或 SaaS。
- 不新增通用 AI 聊天、自动学习诊断或发音评分。
- 不重写现有 Practice、Vault、Review、FSRS 算法和播放器核心。
- 不承诺由 AI 自动获得真实语音素材的版权或签名证书。
- 不在没有上游发行证据时直接发布安装包。

## 使设计失效的证据

- 真实用户即使免配置体验 Demo，也不能理解句级练习价值；此时应重新验证产品教学方法，而非继续优化安装。
- 可恢复导入必须依赖大规模数据模型重构才能成立；此时应拆出独立 OpenSpec，而不是扩大本变更。
- Windows 与 macOS 无法共享同一首次会话和数据契约；此时暂停 Windows 推进并复审平台抽象。
- 目标用户普遍无法或不愿申请外部转写服务密钥；此时本地转写或托管转写需要新的产品与成本决策。
