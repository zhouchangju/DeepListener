# DeepListener 开源适合度评估报告

## 一页结论

- 主要建议：`整理后开源`
- 当前是否可以切 Public：否；先完成两项权属/历史确认。完成后可以低调公开，补齐 Demo 与安装包后再正式推广。
- 开源影响力适配分：79.5 / 100
- 开源价值：43.3 / 55
- 发布准备度：36.3 / 45
- 证据置信度：中
- 一句话理由：产品闭环、真实自用证据和工程验证都很强；本轮已显著改善首次进入体验，但素材/模板权属确认、零配置 Demo 和最终用户安装方式仍决定正式推广效果。

## 决策范围与假设

- “开源”的目标：公开 GitHub 源码并以 MIT 允许外部复用，同时形成可持续的英语学习产品与个人作品。
- 目标用户：愿意使用自己的英语音视频做精听、跟读和间隔复习的学习者；当前安装路径仍优先服务有基础开发能力的用户。
- 维护预算：按仓库现有声明，单人、best-effort、无 SLA、只维护最新主线和 tag。
- 已检查范围：tracked 当前树、ignored 本地表面、完整 Git 历史路径、核心运行路径、测试/构建、治理文档。
- 未检查范围：GitHub 仓库可见性与分支保护等平台设置、作者与雇主之间的权属边界、Agent Harness 模板的再分发授权、部署主机当前加固状态、真实陌生用户可用性测试。

## 四个证据表面

### 当前跟踪文件

- 顶层存在 README、MIT LICENSE、NOTICE、CONTRIBUTING、SECURITY、CODE_OF_CONDUCT、CI 和 53 个测试文件（扫描时计数）。
- 扫描未发现 tracked 密钥模式，也未发现 tracked 媒体或数据库。
- `.env.example` 和 `src/app/api/review/log/route.ts` 是路径/关键词启发式线索，人工复核后分别为占位配置和 API 路由，不是隐私泄露。

### 忽略与本地文件

- 扫描识别到 `.env`、本地数据库、构建输出和大量媒体；它们属于真实用户数据且当前均被忽略。
- 本轮实现前后，`.env`、`prisma/dev.db`、`public/uploads`、`public/videos` 元数据完全一致。

### Git 历史

- 历史路径已检查，仓库不是 shallow clone；没有历史 `.env`、数据库或媒体路径被确认跟踪。
- 早期同步配置中的部署主机仍存在于 Git 对象中，当前树已参数化；它不是凭证，但公开前需要确认该主机已限制访问。
- 历史删除项主要是锁文件和文档，不构成发布阻断。

### 外部平台与治理事实

- 远端指向 GitHub 仓库，但本次未检查 GitHub 可见性、Security Advisory 开关、分支保护、Issue 模板和 Release 页面状态。
- README/SECURITY 已明确单用户、本地或受保护网络、无内建认证；不应将应用直接暴露到公网。

## 已确认阻断项与待确认线索

### 已确认

- 没有已确认的 G1-G4 阻断项。
- 当前首次体验仍要求用户自备合法媒体；没有零风险 Demo。
- 当前安装仍是开发者安装，不是普通学习者的一键安装。

### 待确认

- 业务代码、文档、Agent Harness 模板是否全部由作者拥有或获得公开再分发许可。
- 历史部署主机是否已经采用防火墙、密钥 SSH 和最小暴露面。
- GitHub 平台侧安全与治理设置是否与 SECURITY/维护声明一致。

## 对抗式审查

- 最强反例：产品可能只在作者自己的数据、网络和工作流中顺畅，198 个自动化测试不能替代陌生用户从零安装的可用性测试。
- 隐藏依赖或机会成本：同时维护三家转录 Provider、FFmpeg、Next/Prisma、Docker 和未来桌面端，会迅速超过单人 best-effort 预算。
- 可能被评分误导的地方：文档和 Landing 变漂亮不等于首次成功；真正的关键指标仍是陌生用户能否在 10 分钟内完成一次句级练习。
- 什么证据会改变结论：5 位陌生用户的安装/首次练习记录、首个外部贡献、模板权属确认、合法 Demo、可重复 Docker 升级/备份测试都会显著提高置信度和分数。

## 最小安全发布计划

1. 确认业务代码与 Harness/模板权属；确认历史部署主机已加固；重新运行全历史密钥扫描。
2. 以 `0.3.0-beta.1` 或类似预发布版低调切 Public，启用 Security Advisory、Issue/PR 模板与分支保护，不立即大规模宣传。
3. 提供一段作者自录或权属明确的 30–60 秒音频及可重复 seed/import 流程，让用户无需 Provider Key 体验完整学习闭环。
4. 设计 Docker 持久卷、migration、healthcheck、备份/恢复和升级回滚合同，验证后再发布 Compose。
5. 找 5 位目标用户做“从 README 到完成第一次收藏/复习”的计时测试，修复高频阻塞后再正式发布和推广。

## 最终建议

DeepListener 值得作为旗舰方向继续投入，但当前准确分类仍是 `整理后开源`。本轮已经解决“进门看不懂、环境不知道哪里坏、错误只提示 OpenAI”的核心问题。下一步不要先做通用 AI 聊天；应先完成权属确认、合法 Demo 与可恢复的一键安装。AI 差异化应随后围绕句子级听力难点解释和 Shadowing 反馈展开。
